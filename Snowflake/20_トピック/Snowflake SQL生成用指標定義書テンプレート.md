# Snowflake SQL生成用指標定義書テンプレート

## まず結論

このテンプレートは、AIに `何をどう数えるか` を固定して渡すための定義ファイルです。SQL生成で一番危ないのは文法より `指標の意味ずれ` なので、`定義` `対象条件` `注意` `禁止` を明示します。

## これは何か

売上、購入者数、注文数、継続率などの業務指標を、AIがそのまま参照できる形にしたテンプレートです。Gems に置くと、毎回同じ定義を繰り返し説明せずに済みます。

## どこで使うか

- 指標の意味ずれを防ぎたいとき。
- `COUNT(*)` と `COUNT(DISTINCT ...)` の取り違えを減らしたいとき。
- チーム内で指標定義を共通化したいとき。

## 全体像

- `指標名`
  - 何の指標かを明示する。
- `定義`
  - SQLに落とすとどう数えるかを書く。
- `対象条件`
  - completed のみ、当月のみなどの条件を書く。
- `注意`
  - 混同しやすい点を書く。
- `禁止`
  - やってほしくない解釈を書く。

## テンプレート

```md
# 指標定義書

## この資料は何か
業務上の指標定義をまとめた資料です。
SQL 生成時は、集計方法よりも先にこの定義を優先してください。

## 利用ルール
- 指標名から一般的な定義を推測しない
- 定義がない指標は断定せず、仮定または確認事項として扱う
- COUNT と COUNT DISTINCT を混同しない

## 指標: 売上
定義:
- 売上 = SUM(sales.amount)

対象条件:
- sales.status = 'completed'

注意:
- 税込売上ではなく税抜売上
- 返品控除はこの指標に含めない

禁止:
- cancelled を含めない
- 件数を売上として扱わない

## 指標: 購入者数
定義:
- 購入者数 = COUNT(DISTINCT sales.customer_id)

対象条件:
- sales.status = 'completed'

注意:
- 注文数とは異なる
- 同一顧客の複数注文は1人として数える

禁止:
- COUNT(order_id) を購入者数として使わない

## 指標: 注文数
定義:
- 注文数 = COUNT(DISTINCT sales.order_id)

対象条件:
- sales.status = 'completed'

注意:
- 明細粒度テーブルの場合も注文単位で数える
```

## よくある疑問

### Q. 指標定義書は本当に必要？

A. 必要です。SQL生成では `売上` `会員数` `継続率` のような単語が最も危険です。人間には通じても、AIには候補が複数あります。

### Q. どの指標から作る？

A. まず日常的によく使うものからです。売上、注文数、購入者数、アクティブユーザー数など、誤ると影響が大きい指標を優先します。

## 実務での見方

1. 指標名ごとに1ブロックで書く。
2. `定義` は SQLに落ちる形で短く書く。
3. `対象条件` を省略しない。
4. 混同しやすい指標は `注意` と `禁止` を厚めに書く。

## 次回の確認

- [ ] 指標の数え方を SQLレベルで書いたか。
- [ ] completed などの対象条件を書いたか。
- [ ] 混同しやすい別指標との差を書いたか。
- [ ] 禁止したい解釈を明示したか。

# Snowflake SQL生成用ユーザー依頼文テンプレート

## まず結論

ユーザー依頼文では、`問い` `使うデータ` `条件` `粒度` `出力` を短く揃えて渡します。良い依頼文はお願いではなく、AIがそのまま実装できる `仕様` です。

## これは何か

Snowflake SQL を AI に生成させるときの、毎回の依頼文テンプレートです。システムプロンプトと Gems を前提にしつつ、今回だけ変わる問いや条件を渡すために使います。

## どこで使うか

- 毎回の依頼を短く、でもぶれなく書きたいとき。
- 何を最低限渡せばよいか迷うとき。
- 良い依頼文と悪い依頼文の差を実務で吸収したいとき。

## 全体像

- `目的`
  - 何を知りたいか。
- `使用テーブル`
  - 今回使う対象。
- `カラムの意味`
  - 特に重要な列の意味。
- `結合条件`
  - どのキーで結ぶか。
- `条件`
  - 期間や除外条件。
- `集計粒度`
  - 日別、月別、顧客別など。
- `出力`
  - 欲しい列と並び順。

## テンプレート

```text
Snowflake 用の SQL を書いてください。

目的:
- 何を知りたいか

使用テーブル:
- テーブル名と主要カラム

カラムの意味:
- 重要な日付列や指標列の意味

結合条件:
- どのキーで結ぶか

条件:
- 期間
- 対象範囲
- 除外条件

集計粒度:
- 日別 / 月別 / 顧客別 / 商品別 など

指標定義:
- 売上 = SUM(amount)
- 購入者数 = COUNT(DISTINCT customer_id)

出力:
- 欲しい列
- 並び順

補足:
- 必要なら仮定を明記してよい
```

## 良い依頼文の例

```text
Snowflake 用の SQL を書いてください。

目的:
- 2026年5月の都道府県別売上を集計したい

使用テーブル:
- sales(order_id, order_date, customer_id, amount, status)
- customers(customer_id, prefecture)

カラムの意味:
- order_date = 注文日
- amount = 税抜売上
- prefecture = 顧客の都道府県

結合条件:
- sales.customer_id = customers.customer_id

条件:
- 期間は 2026-05-01 から 2026-05-31
- status = 'completed' のみ

集計粒度:
- 都道府県別

指標定義:
- 売上 = SUM(amount)

出力:
- prefecture, sales
- sales の降順
```

## よくある疑問

### Q. テーブル名だけ渡せばよい？

A. 弱いです。カラムの意味、JOIN条件、指標定義が抜けると、AIが最も危険な部分を推測で埋めます。

### Q. 毎回全部書く必要がある？

A. 共通知識は Gems やシステムプロンプトに寄せてよいです。ただし今回特有の条件、粒度、出力形式は依頼文側で渡します。

## 実務での見方

1. まず目的を1文で固定する。
2. そのあとに使うテーブルと意味を渡す。
3. 条件、粒度、出力の順で具体化する。
4. 毎回の依頼文で変わらない部分は、システムプロンプトや Gems へ移す。

## 次回の確認

- [ ] 目的を1文で書いたか。
- [ ] 重要カラムの意味を書いたか。
- [ ] JOIN条件を書いたか。
- [ ] 条件、粒度、出力を指定したか。

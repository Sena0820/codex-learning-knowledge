# Snowflake SQL生成用JOINルール集テンプレート

## まず結論

このテンプレートは、AIに `どのテーブルを何でどう結ぶか` を固定して渡すための定義ファイルです。JOINの誤りはSQL生成でもっとも結果を壊しやすいので、`結合条件` `標準JOIN` `用途` `禁止` を明記します。

## これは何か

Snowflake SQL 生成時の標準JOINルールをまとめるテンプレートです。スキーマ定義書だけでは不足しやすい、テーブル間の結び方を別ファイルで固定する用途で使います。

## どこで使うか

- AIがJOIN条件を勝手に作るのを防ぎたいとき。
- INNER JOIN と LEFT JOIN の使い分けを標準化したいとき。
- 顧客ID、匿名ID、セッションIDなど、似たキーの混同を防ぎたいとき。

## 全体像

- `結合条件`
  - どのキーで結ぶかを書く。
- `標準JOIN`
  - 通常何を使うかを書く。
- `LEFT JOIN を使う場面`
  - 例外条件を書く。
- `主な用途`
  - どんな分析で使うかを書く。
- `注意` `禁止`
  - キーの意味ずれを防ぐ。

## テンプレート

```md
# JOINルール集

## この資料は何か
テーブル同士の標準的な結合条件を定義した資料です。
SQL 生成時は、この資料にある JOIN 条件を優先してください。

## 利用ルール
- 資料にない JOIN 条件は断定しない
- JOIN 種類は用途に応じて選ぶが、標準ルールを優先する
- キーの意味が一致しないものは結合しない

## ルール: sales と customers
結合条件:
- sales.customer_id = customers.customer_id

標準 JOIN:
- INNER JOIN

LEFT JOIN を使う場面:
- 顧客属性が欠損していても sales を残したいとき

主な用途:
- 都道府県別売上
- 顧客属性別売上
- 会員分析

注意:
- customer_id は両テーブルで同一意味の顧客ID
- 匿名IDやセッションIDとは別物

禁止:
- order_id で customers と結合しない
- prefecture で sales と customers を直接結合しない

## ルール: sales と products
結合条件:
- sales.product_id = products.product_id

標準 JOIN:
- INNER JOIN

主な用途:
- 商品別売上
- カテゴリ別売上

注意:
- product_id の欠損時は用途に応じて LEFT JOIN を検討する
```

## よくある疑問

### Q. スキーマ定義書だけでは足りない？

A. 足りないことが多いです。スキーマ定義書でカラムの存在は分かっても、`通常どのJOINを使うか` `何で結んではいけないか` までは固定しきれません。

### Q. 例外まで書くべき？

A. 書くべきです。LEFT JOIN を使う場面や、同じキー名でも意味が違うケースを書いておくと、AIが一般論で補完しにくくなります。

## 実務での見方

1. よく使うテーブル組み合わせから書く。
2. 各ルールに `結合条件` `標準JOIN` `用途` `注意` `禁止` をそろえる。
3. キーの意味が似ていて危ない組み合わせを優先して明文化する。
4. 例外を認めるなら、その場面を先に書く。

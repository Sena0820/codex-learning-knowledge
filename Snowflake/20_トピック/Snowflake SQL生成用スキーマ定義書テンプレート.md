# Snowflake SQL生成用スキーマ定義書テンプレート

## まず結論

このテンプレートは、AIに `存在するテーブル` `存在するカラム` `各カラムの意味` を誤解なく渡すための定義ファイルです。列名一覧だけでは弱いので、`意味` `注意` `禁止` まで含めて書きます。

## これは何か

Gems や社内ナレッジに置くことを想定した、Snowflake SQL 生成用のスキーマ定義書テンプレートです。AIが一般知識で補完しないように、実在情報を優先させる用途で使います。

## どこで使うか

- AIに分析SQLを書かせる前提資料を作るとき。
- 実在しないカラム名を作らせたくないとき。
- 日付列や金額列の意味ずれを防ぎたいとき。

## 全体像

- `利用ルール`
  - AIがこの資料をどう使うかを固定する。
- `テーブル定義`
  - テーブルの役割と粒度を書く。
- `カラム定義`
  - 列名だけでなく意味を書く。
- `注意`
  - よくある誤解を書く。
- `禁止`
  - 勝手に断定してほしくないことを書く。

## テンプレート

```md
# スキーマ定義書

## この資料は何か
Snowflake SQL 生成時に参照するテーブル・カラム定義です。
SQL 生成では、この資料に存在するテーブル名・カラム名を優先してください。

## 利用ルール
- 資料にないテーブル名やカラム名は作らない
- カラムの意味は一般知識ではなく本資料を優先する
- 不明点がある場合は推測せず確認事項として返す

## テーブル: sales
説明:
- 注文に関する売上データ

粒度:
- 1行が1注文を表す

主キー候補:
- order_id

カラム:
- order_id: 注文ID
- order_date: 注文日
- customer_id: 顧客ID
- product_id: 商品ID
- amount: 税抜売上金額
- quantity: 購入数量
- status: 注文状態

値の例:
- status: completed, cancelled, pending

注意:
- amount は税抜
- order_date は注文日であり、出荷日ではない
- status を条件に入れずに売上集計しない

禁止:
- amount を税込売上として扱わない
- order_date を売上計上日として断定しない

## テーブル: customers
説明:
- 顧客属性データ

粒度:
- 1行が1顧客

主キー候補:
- customer_id

カラム:
- customer_id: 顧客ID
- prefecture: 都道府県
- gender: 性別
- birth_date: 生年月日
- created_at: 会員登録日時

注意:
- prefecture は顧客住所ベースであり、配送先都道府県とは限らない

禁止:
- prefecture を配送先として扱わない
```

## よくある疑問

### Q. カラム名と型だけ書けば十分？

A. 不十分です。AIが外しやすいのは型より意味です。特に `amount` `date` `status` のような一般名は、業務上の意味を明記しないと解釈がぶれます。

### Q. どこまで細かく書く？

A. SQLの意味が変わるところは書きます。粒度、主キー候補、日付の意味、金額の意味、状態値、よくある誤解は優先して書きます。

## 実務での見方

1. まず SQLで使う主要テーブルだけを対象にする。
2. 各テーブルに `説明` `粒度` `主キー候補` `カラム` `注意` `禁止` をそろえる。
3. よく使う値の例がある列は `値の例` を付ける。
4. 仕様が未確定な箇所は空欄にせず `要確認` と書く。

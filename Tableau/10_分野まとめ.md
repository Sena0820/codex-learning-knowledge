# データ可視化の分野まとめ

## まず結論

データ可視化を復習するときは、まず `何をどう見せるか` より `誰にどう届けるか` を先に戻すと整理しやすいです。表現、提供基盤、運用責任の3つに分けると迷いにくくなります。

## どこで使うか

- グラフやダッシュボードを設計するとき。
- 可視化基盤の構成を説明するとき。
- 利用者が迷わず結果を読めるようにするとき。

## この分野の全体像

- `Tableau CloudとTableau Server、クラウド基盤の関係`
  - 可視化基盤の運用責任と階層構造を見るトピック。
- `Tableau抽出でSnowflakeとローカルマスターを組み合わせる運用`
  - SnowflakeのViewとローカルマスターを使い、抽出の増分更新でダッシュボード運用するトピック。
- `TableauのLOD計算と表計算の違い`
  - `FIXED` などのLOD計算と `WINDOW_SUM` などの表計算を使い分けるトピック。

復習の順番:
1. まず `Cloud と Server の違い` を運用責任でつかむ。
2. 次に `tenant > site > project > content` の階層を戻す。
3. 最後に、抽出、増分更新、ローカルファイル更新の運用を確認する。
4. 計算で迷ったら、LOD計算と表計算の違いを確認する。

## よくある疑問

### Q. Tableau Cloud と Tableau Server の違いは何？

A. 本質的な違いは `基盤の運用責任を誰が持つか` です。Cloud は Tableau 側、Server は利用者側が広く持ちます。

### Q. `site` と `project` は何が違う？

A. `site` は大きな作業空間の分離単位、`project` はその中の整理棚であり権限モデルの中心です。詳しくは [Tableau CloudとTableau Server、クラウド基盤の関係](./20_トピック/Tableau CloudとServerとCloud階層の違い.md) を見ます。

### Q. 可視化の話なのに、なぜ基盤の整理を入れるの？

A. ダッシュボードの見やすさだけでなく、誰にどう届け、どう管理するかまで含めて可視化基盤だからです。実務ではこの運用面で詰まりやすいです。

### Q. Snowflakeのデータを毎日全件読み直さずにTableauで使えますか？

A. 抽出データソースにして、`loaded_at` や `business_date` などの増分判定列を使えば、毎日新しい行だけ追加する運用ができます。ただし、ローカルマスターの変更を過去行へ反映したい場合はFull Refreshが安全です。詳しくは [Tableau抽出でSnowflakeとローカルマスターを組み合わせる運用](./20_トピック/Tableau抽出でSnowflakeとローカルマスターを組み合わせる運用.md) を見ます。

### Q. TableauでSQLのWindow関数のような計算はできますか？

A. できます。Tableauでは `WINDOW_SUM` `RUNNING_SUM` `LOOKUP` `RANK` などの表計算として使います。`FIXED` などのLOD計算は集計粒度を決める道具、表計算は表示された結果の上で方向や範囲を決めて計算する道具です。詳しくは [TableauのLOD計算と表計算の違い](./20_トピック/TableauのLOD計算と表計算の違い.md) を見ます。

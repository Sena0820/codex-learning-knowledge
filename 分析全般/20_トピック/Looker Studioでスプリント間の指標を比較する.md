# Looker Studioでスプリント間の指標を比較する

## まず結論

スプリントが日付ではなく `Sprint 10` `Sprint 11` のようなディメンションなら、期間コントロールではなくスプリント選択用のプルダウンを使います。

期間A・期間Bの値に加えて差分や増減率まで表示するには、2つの選択値を同じ計算の中で参照できるようにします。候補を手動管理できるなら `パラメータ方式`、候補を元データから自動更新したいなら `自己統合方式` が基本です。

## これは何か

Looker Studioで2つのスプリントを選び、次の4つをスコアカードで比較するための設計を整理したノートです。

- スプリントAの指標
- スプリントBの指標
- 差分: `A - B`
- 増減率: `(A - B) / B`

通常のプルダウンを別々のグループに置くだけでは、A側とB側の集計結果を3枚目のスコアカードから直接参照できません。差分を出すには、AとBを同じデータ構造または同じ計算式の中へ載せる必要があります。

## どこで使うか

- 今回のスプリントと前回のスプリントを比較するとき
- 任意の2スプリントを利用者に選ばせたいとき
- 件数、売上、ポイント、工数などの差をスコアカードで見せたいとき
- 新しいスプリントが追加されても選択候補を追従させたいか判断するとき

## 全体像

まず、プルダウンの役割を2種類に分けます。

| 方式 | 選択肢 | 長所 | 注意点 |
| --- | --- | --- | --- |
| パラメータ方式 | 許可値として登録 | 計算が単純で安定する | 新しいスプリントを候補へ追加する運用が必要 |
| 自己統合方式 | 元データのディメンション値 | 候補を自動更新できる | 統合設定と集計粒度の管理が必要 |

最も単純な構成はパラメータ方式です。

```text
[Sprint A ▼]  [Sprint B ▼]
       |              |
       +------v-------+
              |
    AとBを条件集計する
              |
  +-----------+-----------+-----------+
  |                       |           |
[Aの値]                [Bの値]     [A-B]  [(A-B)/B]
```

プルダウンA・Bを別グループの通常フィルタとして作るだけでは、差分スコアカードが両方の集計値を受け取れません。差分まで必要なら、選択値を計算に渡せるパラメータ、またはA側・B側を1つにした統合データを使います。

## よくある疑問

### Q. 通常のプルダウンを2つ置くだけではだめか

A. AのスコアカードとBのスコアカードを別々に絞るだけなら可能です。しかし、別グループで集計された2つの表示結果を、3枚目のスコアカードから直接参照することはできません。

### Q. 最も簡単なパラメータ方式はどう作るか

A. テキスト型の `選択Sprint_A` と `選択Sprint_B` を作り、それぞれをプルダウンコントロールへ割り当てます。スプリント名を許可値として登録し、計算フィールドで元データの `Sprint` と比較します。

スプリントAの例:

```text
SUM(
  CASE
    WHEN Sprint = 選択Sprint_A THEN 実績値
    ELSE 0
  END
)
```

スプリントBの例:

```text
SUM(
  CASE
    WHEN Sprint = 選択Sprint_B THEN 実績値
    ELSE 0
  END
)
```

差分は、Aの条件集計からBの条件集計を引きます。

```text
差分 = スプリントAの値 - スプリントBの値
```

増減率はBを基準にします。

```text
増減率 = (スプリントAの値 - スプリントBの値) / スプリントBの値
```

Bが0の場合はゼロ除算を避ける条件を追加します。

### Q. スプリント候補を自動で増やしたい場合はどうするか

A. 同じデータソースをA側・B側として自己統合し、統合後の `Sprint_A` と `Sprint_B` を通常のプルダウンへ割り当てます。

```text
A側: 結合キー / Sprint_A / 実績値_A
B側: 結合キー / Sprint_B / 実績値_B
結合: 固定の結合キー同士
計算: 実績値_A - 実績値_B
```

この方式では、両プルダウンとすべてのスコアカードを同じ統合データに接続します。プルダウンは単一選択にし、未選択や複数選択による重複集計を避けます。

### Q. パラメータ方式と自己統合方式のどちらを選ぶか

A. まずパラメータ方式を検討します。スプリント候補の自動更新が必須で、許可値の手動更新を避けたい場合だけ自己統合方式を使います。

## 実務での見方

### パラメータ方式の作成手順

1. `選択Sprint_A` と `選択Sprint_B` をテキスト型パラメータとして作る。
2. 各パラメータへ選択可能なスプリント名を登録する。
3. パラメータを操作するプルダウンを2つ配置する。
4. A、B、差分、増減率の計算フィールドを作る。
5. 4つの計算結果をスコアカードへ配置する。
6. Bが0の場合と、A・Bに同じスプリントを選んだ場合を確認する。

### 自己統合方式の作成手順

1. 元データを `1スプリント × 必要な比較粒度` まで集計する。
2. 同じデータソースを統合データへ2回追加する。
3. A側に `Sprint_A`、B側に `Sprint_B` を用意する。
4. 固定キーでA側とB側を結合する。
5. 統合後のフィールドからA・B用のプルダウンを作る。
6. `実績値_A - 実績値_B` と増減率をグラフ固有の計算フィールドとして作る。
7. 2つのプルダウンを単一選択にする。

### 集計粒度の注意

自己統合で元データに複数行が残っていると、A側とB側の組み合わせが増えて指標が膨らむ可能性があります。JOIN前後の件数と、スプリントごとの一意性を確認します。

GA4など、コネクタ側ですでに集計された指標は再集計できない場合があります。その場合はBigQueryやスプレッドシートなどで、比較用の完成データを先に作る方が安定します。

## 次回の確認

- [ ] スプリントは日付ではなくディメンションとして管理されているか
- [ ] A・Bの選択値を同じ計算から参照できる構成か
- [ ] スプリント候補の手動更新を許容できるか
- [ ] 自己統合を使う場合、元データは比較粒度で一意か
- [ ] プルダウンは単一選択になっているか
- [ ] 差分の向きは `A - B` で合っているか
- [ ] 増減率の基準はBで合っているか
- [ ] Bが0の場合を処理しているか
